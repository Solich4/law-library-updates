# Обновления

Приложение работает офлайн. При открытии оно проверяет latest.json не чаще раза в сутки; есть ручная проверка. Закрытое приложение в фоне обновления не скачивает. Материалы обновляются отдельно от APK: манифест указывает JSON-пакет, его SHA-256 и ECDSA-подпись. Только после проверки подписи, структуры и сохранения документов пакет атомарно заменяет прежний. При ошибке остаётся последняя рабочая редакция. Проверенный неизменившийся пакет повторно не скачивается. Закладки и порядок документов хранятся отдельно на телефоне.

Сам APK обновляется установкой новой версии с той же подписью. Данный механизм не загружает исполняемый код.

Workflow мониторинга рассчитан на проверку официальных публикаций и активных/будущих редакций раз в шесть часов. GitHub может задерживать расписание и отключать его в неактивном публичном репозитории; запуск также доступен вручную. Ошибки и возможный пропуск окна RSS фиксируются как проблемы. Отсутствие найденных изменений не служит юридическим подтверждением актуальности.

Обнаружение изменения, восстановление полного текста, переработка пояснений, проверка и подпись — разные этапы. Монитор только создаёт очередь .monitor/, не переписывает и не подписывает законы. Автоматическая подготовка юридически проверенных пояснений пока не реализована. Без подготовки и публикации подписанного пакета изменение закона само в телефоне не появится. Закрытый ключ остаётся у издателя.

Локальная проверка редакций 26 документов прошла. Живой RSS получил по 200 публикаций из двух лент. HTTPS из среды сборки завершился сетевым тайм-аутом; использован явно отмеченный HTTP-резерв только как недоверенный сигнал для очереди проверки. Он не разрешает менять тексты или подписывать обновления. Workflow опубликован; первый ручной запуск в GitHub Actions успешно прошёл 23.10.2026: https://github.com/Solich4/law-library-updates/actions/runs/39977114942. Расписание настроено на каждые шесть часов, фактическое время запуска определяется GitHub.

Раздел «Изменения» в клиенте показывает публичную очередь событий для проверки. Проверяется при открытии не чаще раза в шесть часов и вручную; фоновых проверок нет. Баннер ожидания обновления не означает, что новый текст уже установлен. Не каждая новая публикация обязательно меняет документы библиотеки. После разбора и выпуска материалов издатель должен закрыть обработанные события и обновить проверенную базу мониторинга.
